# Stage 00 — Preseason hardening

Eleven tasks. Each file is one Replit task, one PR, one verification. Run them in filename
order. Do not batch two files into one task — each is sized for a single agent context window.

**The governing constraint: tasks 00–03 ship before any other task in this folder.** Tasks 04
through 10 all require a deploy, and a deploy is the operation that has previously lost ledger
data. Do not change schema until a verified recovery path exists.

## Order and grouping

| | Task | Deploys? |
|---|---|---|
| `00` | Read-only backup role and the logical snapshot exporter | no |
| `01` | Nightly backup workflow to a private repository | no |
| `02` | Snapshot comparison tool and the documented restore drill | no |
| `03` | Row-count drop detector with Slack alerting | no |
| `04` | Make the drizzle-kit push diff converge | yes |
| `05` | CI gate asserting an empty push diff | yes |
| `06` | Guard the destructive team delete | yes |
| `07` | Protect manually entered metrics from the event sync | yes |
| `08` | Startup migration escape hatch | yes |
| `09` | Pin the canonical public origin | yes |
| `10` | MCP OAuth connection stability | yes |

Tasks `09` and `10` must ship in the same deploy window. Both invalidate cached MCP client
metadata, so shipping them separately forces every user to reconnect twice instead of once.
Announce one reconnect window to the pool and do both inside it.

## Prerequisites to complete by hand before starting

1. **Private backup repository.** Create `cthompson9/Calcutta-Backups` as a private repo with a
   single empty initial commit on `main`. Task `01` needs it to exist.
2. **Fine-grained PAT** scoped to `Calcutta-Backups` only, with Contents: read and write. Store
   it in the `Calcutta-Website` repository secrets as `BACKUP_REPO_TOKEN`. Do not use a
   classic token and do not grant it access to `Calcutta-Website`.
3. **`DATABASE_URL` and `BACKUP_DATABASE_URL`** in `Calcutta-Website` repository secrets.
   `BACKUP_DATABASE_URL` should use the read-only role created in task `00`; add it after that
   task lands.
4. **Slack incoming webhook** for whichever channel should receive backup alerts. Store as
   `SLACK_BACKUP_WEBHOOK`. Task `03` needs it.
5. **Custom domain** — DONE. `https://www.thecalcutta.app` is live on the Replit deployment and
   published. The canonical origin for task `09` is exactly `https://www.thecalcutta.app` —
   https, www, no trailing slash. Confirm the apex `thecalcutta.app` is also registered in Replit
   and 301s to the www host, since users will type it without the prefix.

   Until task `09` ships, do not publish the new MCP endpoint URL to the pool. The app already
   advertises the new host as its OAuth issuer, so a connector added on it now is registering
   against an unpinned identity and will need re-adding during the 09/10 window anyway. The URL
   to announce at that point is `https://www.thecalcutta.app/api/mcp`.
6. **Confirm the production database is reachable from GitHub Actions** before task `01`. If it
   is not, stop and say so — tasks 01 through 03 need redesigning around an authenticated
   endpoint instead of a direct connection.

## Deferred

`prompts/stage-00-preseason/deferred/11-surgical-snapshot-importer.md` is in-season work, not
preseason. Rationale: as long as the snapshot bytes exist, the importer can be written at
recovery time. If the bytes do not exist, no importer helps. Capturing the data is urgent;
consuming it is not.
