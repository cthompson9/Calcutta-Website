Good — then two simplifications and one new table.

**1. Dated membership table**

```sql
consortiums (id, name UNIQUE)

bidders (id, name UNIQUE)   -- no consortium FK anymore

consortium_memberships (
  id,
  bidder_id FK,
  consortium_id FK,
  from_date DATE,
  to_date DATE NULL,        -- NULL = current
  -- no overlapping active memberships per bidder:
  EXCLUDE USING gist (bidder_id WITH =, daterange(from_date, to_date) WITH &&)
)
```

The merger case works like this: Greg K and Zach L each keep their bidder rows forever — those are the identities that positions point at. Their old solo consortiums get `to_date` set, and both get new membership rows in the merged consortium. Nothing about historical positions changes.

This gives you both rollup flavors for free, and you should decide which is the default in reports:

- **As-of-then:** join memberships on the Calcutta's year/date → Greg K's 2024 returns show under his solo consortium, exactly as the pool experienced it. Right answer for historical leaderboards.
- **As-of-now:** join on `to_date IS NULL` → the merged consortium's "all-time" record absorbs both members' histories. Right answer for "what's this consortium's lifetime P&L."

I'd make as-of-then the default anywhere you display past seasons, and offer as-of-now as an explicit "lifetime by current roster" view. Otherwise the first merger silently rewrites every historical leaderboard.

Practical detail: give each Calcutta an `as_of_date` (or just derive from year + sport season start) so the membership join has a deterministic anchor date rather than joining on "sometime during 2024."

**2. Cost basis stays simple**

Since the season-ending owner gets full season value, drop `effective_from_period_id` entirely. Effective ownership is just the current signed sum per (entry, bidder), and every period's return — realized and MTM, all 23 periods — is computed against that current ownership. A mid-season trade instantly restates the buyer's and seller's MTM series for the whole season, which is actually correct under your rule: the position's value *is* the season-long claim.

One subtle consequence worth confirming: this means historical MTM reports aren't frozen. If someone looks at "Week 7 MTM by owner" after a Week 12 trade, the Week 7 numbers reflect Week 12 ownership. If you ever want "what did the leaderboard look like at the time," you'd snapshot owner-level returns per period as a materialized report table — but that's a display cache, not schema truth, and can be added later without migration pain.

Final assembled join path for the cross-everything rollup:

```
consortium ← membership (dated) ← bidder ← position → entry → calcutta
                                              ↓
                                    entry_period_returns (derived)
```

Sum `pct × entry_return` at whatever grain you want — period, Calcutta, sport, year, or all-time — and pick the membership join date per the rollup flavor. No stored owner-level return values anywhere.
