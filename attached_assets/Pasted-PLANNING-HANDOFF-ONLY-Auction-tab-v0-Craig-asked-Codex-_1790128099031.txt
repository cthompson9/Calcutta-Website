## 2. Page layout and permissions

Keep the existing /dashboard route so old links continue working. Change desktop/mobile navigation and page title to Auction. Do not rename the separate /results results-analysis page.

Top to bottom:

1. Existing Calcutta/season selector and Auction title; clear setup/live/complete state; admin unlock.
2. Metrics: Pool Size, Lots Sold / Total Lots, Average Sale Price. Clearly label inclusion of the current live bid in pool size.
3. On the Block: large lot name, nomination number, current bid, recognized consortium or Bidder unknown, status Bidding / Sold / Needs review. Show split percentages for a completed shared purchase. A completed lot stays here until the next nomination.
4. Admin nomination button and listener connection/recording status. Admin actions: pair listener, start/stop recording through the local app, edit current bid/buyer, finalize manually, amend sale. Recording does not start just because Launch is clicked.
5. Consortium List beside On the Block on desktop and below on mobile. Read-only names for viewers; admin add/edit names and spoken aliases. Provide a split editor with consortium selectors and percentage fields.
6. Live transcript preview, with interim/final distinction, connection state, last received time, and bounded scrollback. Preserve scroll position when reading older lines. Admin sees review/error details and correction controls; viewers see transcript and auction state without credentials or diagnostics.
7. Existing results ledger and Points Rubric. Preserve original sale order and original buyers separately from later trade ownership. Results update on finalized sales/corrections.
8. Admin lot inventory panel: add/import/edit lots, availability status, validation errors, totals. Empty setup state explains how to upload lots. Completed auctions show this read-only.

Use existing typography, colors, cards, spacing and admin pattern. Keyboard-accessible controls and labeled form errors; announce nomination and finalized sale changes without announcing every partial transcript. At narrow widths avoid horizontal page overflow.

All write restrictions are enforced server-side, including direct HTTP and MCP calls. Hiding buttons is not authorization. Scope all data and streams to explicit calcuttaId AND auctionId, never infer an auction from a default NFL year.

## 3. Auction state machine

Auction states: setup -> live -> complete. Lot states: available -> bidding -> sold. At most one bidding lot per auction. Keep currentLotId after sale for display. No skip, pass, reset-to-queue, or automatic voice nomination.

| Condition | Button | Behavior |
|---|---|---|
| No lots | Launch, disabled | Explain that lots must be loaded |
| No lot nominated, inventory valid | Launch | Atomically choose one available lot and start auction |
| Current lot bidding; other lots available | Start Next Item, disabled | Finish current sale first |
| Current lot sold; available lots remain | Start Next Item | Atomically choose one available lot |
| Last available lot now bidding | End Auction, disabled | Final sale must be resolved |
| Every lot sold | End Auction | Confirm completion summary, then freeze auction |
| Auction complete | Auction Complete, disabled | Historical read-only state |

The server randomly selects uniformly from available lots inside the same transaction that marks nomination and records its order. Do not let the browser pick or reshuffle on refresh. Persist nomination ID, sequence, timestamps and random selection outcome. Double clicks/retries reuse an idempotency key; concurrent admins cannot nominate two lots. Requests with stale revision return conflict plus refreshed state.

Launch requires a nonempty valid lot set. Consortia can be added during bidding because participants may be unknown initially. A sale requires a valid price and fully resolved allocation before it counts as sold. Recommended v0 price rule: positive USD amount to cents; never substitute zero for a missing price. Zero-dollar explicit sales, if desired later, are a separate validation decision.

Before completion, admins may edit labels/aliases/metadata for any lot. Available lots may be added or removed with an audit trail and total count recalculation. A nominated/sold lot cannot be silently deleted, replaced with a different economic asset, or removed to evade the all-lots-sold rule. Correct a mistaken nomination's descriptive label in place only if the underlying lot is unchanged. Adding a lot after the previous last sale changes the button back to Start Next Item. End Auction rechecks the entire inventory transactionally.

Completed inventory is frozen. Commissioner sale corrections remain a separate audited operation, subject to existing trade protections; they do not reopen bidding or replace original nomination order. Do not add a general auction-reset feature in v0.

## 4. Consortium identity and splits

Maintain an auction-specific roster of stable consortium IDs, display names and speech aliases. Names are unique after case/whitespace normalization within an auction; aliases cannot ambiguously identify two active consortia. Renaming preserves ID and sale history. Referenced consortia cannot be destructively removed; retain historical identity.

Do not equate audio speaker labels with buyers. Recognize the named bidder in auctioneer speech; if a price is clear but buyer is not, show Bidder unknown rather than carrying the previous buyer forward. Never auto-create a consortium from transcription. Admin can add the actual consortium and resolve the pending sale.

Single buyer means 100%. Shared sale stores an allocation list; each selected consortium appears once, each percentage is positive, and the sum must be exactly 100%. Unequal percentages are supported. Use fixed decimal/integer arithmetic and the repository's existing ownership precision rules, not floating-point equality. Missing percentages on a shared sale require resolution; do not assume an equal split unless speech explicitly says equal/half etc. UI may offer an explicit Equal split action.

The current global consortia and consortium_memberships tables represent a different, cross-auction grouping model. Add an auction roster/mapping rather than rewriting global membership when an auction consortium is renamed. Explicitly map each buying consortium to the existing ownership-ledger identity (bidderId); preserve existing historical mappings. For newly created buyers, create/link the compatible ledger identity transactionally and prohibit ambiguous name-based cross-auction matching.

## 5. Speech ingestion and finalization

Flow: Windows audio -> existing Recall streaming transcript -> authenticated event bridge -> server interpretation/validation -> transactional auction state -> realtime viewers.

Use the existing local capture and durable outbox, but replace the rehearsal's voice-nomination behavior. Transcript events cannot select a team. Lot references in speech can confirm the current lot or flag a mismatch; they never override the button selection.

Implement structured events for transcript partial/final, bid observed, sale proposed, sale finalized, review required, correction, listener status. The authoritative server validates/derives auction mutations from transcripts; never trust arbitrary client sale payloads as committed ledger writes. Reuse bounded deterministic parsing for supported bid/sale language, then extend against recorded test fixtures. If an LLM fallback is added, constrain output to a schema and supplied roster/current lot, validate identically, and keep it out of the ordinary fast path.

Recognize actual bids separately from asks: 'I have 500' is a bid; 'do I hear 600?' must not raise the price. 'Once' and 'twice' alone never finalize. Negated/retracted 'not sold' and ambiguous numbers go to review. Only an explicit completed-sale statement with amount and resolved buyer/allocation finalizes automatically. Assemble fragmented final transcript segments within the same utterance/context; do not join unrelated speech across lots.

Partial transcripts can display a provisional bid promptly. Replace revised partials rather than appending duplicates. Do not permanently finalize a sale from a revisable partial. The accepted live amount normally increases; an explicit correction can decrease it, with provenance. Provisional status must be visible when included in pool size.

Event envelope: unique event ID, source recording/session ID, provider utterance ID/version, source audio timestamps, receivedAt, auctionId, nominationId/context epoch, and expected auction revision where appropriate. Persist dedup keys so retries after restarts are harmless. At nomination boundaries map audio time to the correct nomination interval; stamping only currentLotId at delayed callback arrival is unsafe. Unknown, delayed or overlapping boundary events are held for review. Manual corrections supersede earlier automatic events; replay must never overwrite them.

Persist final transcripts, bids, sales, review decisions and a transactional event/outbox row before broadcasting. Bound ephemeral partial data and viewer scrollback. One active capture lease per auction avoids duplicate independent recordings; a reconnect resumes the same lease or explicitly replaces it. Stop/revoke ingestion on completion. Disconnects show visibly and preserve local queued events. Replays of old events are validated against their original lot and revision, not applied to whichever lot is now current.

Unknown buyer/split/price: display Needs review and retain the pending transcript. Do not count it sold or enable the next nomination until admin resolves it. Manual entry remains available if audio is interrupted. Corrections include actor, before/after values, timestamp and reason/source.

Latency objective remains less than one second from end of completed sale speech to visible website update. Measure end-to-end, including provider finalization; do not claim the tested microphone path proves this guarantee. Also measure ingestion-to-commit and commit-to-render independently. Target app-side p95 below 300 ms on the deployed test environment, leaving room for provider delay. If final transcripts exceed the end-to-end target, show provisional recognition promptly and report the measured limitation; do not sacrifice sale correctness to imply an SLA.

## 6. Data model and ledger integration

Suggested additive Drizzle tables (adapt names to current conventions):

- auction_sessions: calcuttaId, status, currentLotId, revision, created/started/completed timestamps; only one active session per Calcutta.
- auction_lots: auctionId, stable externalId, displayName, aliases/metadata, optional existing entry/team association, status, nominationId/order, current bid cents, live bidder/allocation, revision.
- auction_consortia: auctionId, displayName, aliases, ledger bidderId mapping, active flag.
- auction_sales and auction_sale_allocations: one current sale per lot, total cents, buyers and exact shares, ledger linkage, source event, revision. Preserve versions through audit history.
- auction_events/review items: persistent dedup, event sequence, actor/source, nomination context, before/after, transcript references and review outcome.
- listener_sessions: auction-scoped revocable capability/lease, expiry and connection health. Store token hashes, not plaintext reusable tokens.

Database constraints enforce scope, one sale per lot, no duplicate allocation, valid amounts and shares. Use the existing per-season ownership advisory lock BEFORE reading/reloading ownership state; acquire locks consistently with existing write paths. In ONE transaction validate state, write sale/allocation, update canonical primary positions/cost basis, write ownership audit and auction event, and advance revision. Publish only after commit. A failure rolls back all these changes.

Use shared domain services for UI/API/MCP/capture paths. Do not create a parallel price ledger that disagrees with existing summary/results/analysis. Preserve original buyers and nomination order for Auction results even after ownership trades. Respect existing prohibition on rewriting primary ownership after approved trades; surface its established correction workflow.

Allocate dollar cost basis to split owners in integer cents with deterministic residual distribution so parts sum exactly to the sale total. Do not independently round every owner's share and lose/gain cents. Split sale totals count once.

Generic lot model must not hard-code 32 NFL teams. Current calcutta_entries requires team association and existing Dashboard is NFL-gated. For ordinary team lots, link the existing entry explicitly. For non-team/bundled lots, define a compatible entry mapping before enabling that inventory type; do not invent fake NFL teams. Preserve existing historical views until their mapping is verified. Support variable lot counts immediately.

Existing auctions must not suddenly become live drafts. No automatic historical backfill/reinterpretation. New sessions are explicit and cannot accidentally overwrite a populated completed auction. Use additive versioned migrations in the existing migration runner and schema-convergence workflow; no destructive production schema push.

Bulk upsert accepts auction ID, expected revision, idempotency key and lots [{externalId, name, aliases, entryId/teamId?, metadata?}]. Include dry-run validation. Use SSE or equivalent supported push with a database-backed sequence/outbox, initial snapshot plus after-sequence catch-up, reconnect dedup, heartbeat and gap-triggered snapshot refresh. ## 8. Metrics

Let F = sum of finalized sale totals, L = current lot's live amount only while it is bidding, N = finalized lot count, T = current retained lot count.

- Pool Size = F + L. No live amount means L = 0.
- Lots Sold = N / T; nomination does not increase N.
- Average Sale Price = F / N; display an em dash when N = 0.

Once current lot sells, its price belongs to F and L becomes zero, even though On the Block continues showing the sale. Example: finalized prices $100 and $300, current live $150 -> pool $550, sold 2/T, average $200. Finalize current at $150 -> pool still $550, sold 3/T, average $183.33. Split percentages do not change pool totals or lot count. Corrections recompute all metrics from canonical data.
